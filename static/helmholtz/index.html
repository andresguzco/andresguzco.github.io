01

How the repo works

Three things to internalise before touching anything.

One entry point. Everything runs through rla_pinns/train.py. General flags (--equation, --dim_Omega, --N_Omega …) are parsed first; each optimizer then parses its own prefixed flags (--RNGD_damping, --KFAC_ema_factor …). Unrecognised flags are a hard error, by design.

An "equation" is a module plus registrations. A PDE lives in one file (e.g. rla_pinns/poisson_equation.py) that exports four functions, and its string name is then added to about eight dispatch tables scattered across train.py, linops.py and the optimizers. There is no plugin registry — the tables are literal dicts. Miss one and you get a KeyError only when that optimizer runs.

Speed comes from the forward-Laplacian. Derivatives are not taken with plain autograd. manual_forward_laplacian pushes exactly three quantities through the network layer by layer — the value, the directional gradients, and the summed second derivatives:

  • forwardu — the layer's value
  • directional_gradients∂u/∂xᵢ for each input coordinate
  • laplacianΔu (or a coordinate subset)

Every fast optimizer in the paper (RNGD/SPRING/ENGD-Woodbury, KFAC) builds its Jacobian directly out of those three slots. This is the hard constraint on any new PDE: the interior residual must be an affine combination of u, ∇u and Δu at each point. Helmholtz fits exactly — it uses forward and laplacian. Anything needing third derivatives, a complex-valued output, or coupled outputs does not, and would be a much larger change.

02

The problem to set up

Time-harmonic Helmholtz on the unit cube, with a manufactured reference solution.

The PDE

A Wi-Fi emitter radiating at a fixed frequency is a time-harmonic source. Strip the e-iωt and the field obeys the Helmholtz equation Δu + k²u + f = 0, with f the emitters and k the wavenumber. Follow the repo's existing sign convention: Poisson is written residual = laplacian + y, so the target y plays the role of -Δu. For Helmholtz, residual = laplacian + k²·u + y.

Work on the unit cube, not on metres

All sampling in this repo is hard-wired to [0,1]d. Do not fight that — non-dimensionalise instead. For a cubic room of side L at frequency f, the dimensionless wavenumber is 

k̃ = 2π f L / c        # c = 3e8 m/s

Set --dim_Omega=3 and use k̃ in the residual. Everything else — the boundary sampler, the eval grid, the plots — keeps working unchanged.

This is the main risk — read it before scoping

Real Wi-Fi is very high frequency for a PINN. At 2.4 GHz the wavelength is 12.5 cm, so a 5 m room is 40 wavelengths across and k̃ ≈ 251. A tanh MLP with ~10⁵ parameters will not resolve that, and no optimizer in this paper fixes it — it is an approximation-capacity problem, not an optimization problem.

For a feasibility test, start at k̃ ≈ 6–20 (one to three wavelengths per side) and run a k-scaling study: fix everything else and sweep k̃ ∈ {6, 12, 25, 50}. The honest deliverable is the curve of "achievable L2 error vs. k̃ at fixed budget", plus how much of the gap the second-order optimizers close versus Adam. Frame the study that way from the start — it answers the real question, where a single run at full frequency only produces a failure.

You need a closed-form reference solution

train.py logs l2_error against SOLUTIONS[equation][condition], and every sweep's objective is l2_error. Without an analytic solution the sweeps have nothing to rank and the whole pipeline is inert. Use the method of manufactured solutions: pick u*, then define y = -(Δu* + k²u*) and take the boundary target from u* itself.

The natural choice — analytic, oscillatory, and physically a room — is a superposition of standing modes, each term a "source" with its own amplitude: 

u*(x) = Σⱼ Aⱼ · Πᵢ sin(mⱼᵢ · π · xᵢ)

Δu*    = -π² Σⱼ Aⱼ (Σᵢ mⱼᵢ²) · Πᵢ sin(mⱼᵢ π xᵢ)
y      = Σⱼ Aⱼ (π² Σᵢ mⱼᵢ² - k̃²) · Πᵢ sin(mⱼᵢ π xᵢ)

This vanishes on the walls (perfectly reflecting boundary), so the boundary targets are zero and the physics is a closed room. If you later want lossy or non-uniform walls, swap in Gaussian bumps centred at emitter positions — inhomogeneous Dirichlet data needs no code change, because create_condition_data already evaluates u(X_dOmega) for its targets.

Pick k away from resonance

The Dirichlet Helmholtz problem is only uniquely solvable when k̃² is not an eigenvalue of -Δ, i.e. k̃² ≠ π²(n₁²+n₂²+n₃²) for every integer triple. At or near a resonance the solution is non-unique, the Gramian picks up a near-null direction, and the damping sweep will look mysteriously unstable. Choose k̃² strictly between two consecutive eigenvalues and note the choice.

03

The equation module

Create rla_pinns/helmholtz_equation.py by copying poisson_equation.py.

Copy rla_pinns/poisson_equation.py verbatim. Only three things change; the two large boilerplate functions at the bottom (evaluate_interior_loss_and_kfac and evaluate_interior_loss_with_layer_inputs_and_grad_outputs) are generic and must be copied unmodified — they already handle a residual that reads both the forward and the laplacian slot.

a. The residual

K = 12.0  # dimensionless wavenumber; overwritten from the CLI


def set_wavenumber(k: float) -> None:
    """Set the module-level wavenumber. Called once from train.py."""
    global K
    K = k


def evaluate_interior_loss(model, X, y):
    # autograd path (used by tests and by ENGD's Sequential model)
    if isinstance(model, Module):
        intermediates = None
        input_hessian = autograd_input_hessian(model, X)
        laplacian = einsum(input_hessian, "batch i i -> batch").unsqueeze(-1)
        u = model(X)
    # forward-Laplacian path (used by every fast optimizer)
    elif isinstance(model, list) and all(isinstance(l, Module) for l in model):
        intermediates = manual_forward_laplacian(model, X)
        laplacian = intermediates[-1]["laplacian"]
        u = intermediates[-1]["forward"]
    else:
        raise ValueError(...)

    residual = laplacian + K**2 * u + y          # <-- the only physics line
    return 0.5 * (residual**2).mean(), residual, intermediates

b. The solution and forcing

Add u_room_modes(X) and f_room_modes(X) implementing the two formulas from section 02. Keep the mode list at module level; its length must equal --dim_Omega. Both take (N, d) and return (N, 1).

c. Making k configurable

The optimizers capture references to the module-level function objects at import time, so a module global read at call time is the cheapest way to make k sweepable. Add --wavenumber to parse_general_args in train.py (required — check_all_args_parsed() raises on any unconsumed flag) and call helmholtz_equation.set_wavenumber(args.wavenumber) once at the top of main(). It then lands in the wandb config automatically, since config = vars(args) | ….

Why the boilerplate needs no edits

In evaluate_interior_loss_with_layer_inputs_and_grad_outputs, the layer inputs are already stacked as [forward, directional_gradients, laplacian] and grad(residual, layer_outputs, …) is already asked for all three slots of every layer. Under Poisson the last layer's forward gradient comes back empty (hence allow_unused=True, materialize_grads=True); under Helmholtz it comes back populated. Same code, correct either way.

05

Sampling

Mostly already done. Here is what exists and what is worth changing.

Interior points come from create_interior_data — uniform rand(N, d) on the unit cube, with targets y = f(X). Boundary points come from square_boundary(N, d) in poisson_equation.py:36: uniform points on the faces of the cube, with targets u(X_dOmega). Reuse both as-is.

--batch_frequency=1 resamples fresh points every step; that is what every sweep in the paper uses, and it is the right default here. --N_eval (default 10 × N_Omega) is a fixed, separate grid used only for the logged l2_error.

Two changes worth considering

  • Localised emitters. If you move to tight Gaussian sources instead of modes, uniform interior sampling will under-resolve them. Either widen the sources, or concatenate a source-centred oversample into create_interior_data.
  • Non-cubic rooms. Rescaling a box L₁×L₂×L₃ to the unit cube turns the Laplacian into an anisotropic Σᵢ Lᵢ⁻² ∂ᵢ². This is already supported: manual_forward_laplacian(layers, X, coefficients=A) computes a weighted sum of second derivatives — pass A = diag(L₁⁻², L₂⁻², L₃⁻²). Do the cubic case first; reach for this only if the room shape is part of the question.
06

Validate before spending GPU hours

One test matters far more than the others.

The consistency test

Copy test/test_poisson_equation.py::test_evaluate_interior_loss into test/test_helmholtz_equation.py. It compares the autograd path (Sequential model) against the forward-Laplacian path (list of layers) and checks the parameter gradients match.

Why this is the one test to get right

SGD and Adam use the autograd path. Every fast optimizer uses the forward-Laplacian path. If the two disagree, the baselines will look perfectly healthy while ENGD-Woodbury and SPRING silently optimize the wrong objective — and you will read that as "the method doesn't transfer". Run this test before anything else.

One difference from the existing tests: they build the final layer with Linear(2, 1, bias=False), because for Poisson and heat the last bias does not affect the residual. Under Helmholtz it does, through the k²u term — so keep bias=True and drop that comment.

Integration smoke test

Add ("helmholtz", "room_modes") to the equation lists in test/test_train.py (there is one per optimizer block), then: 

pytest -vx test/test_helmholtz_equation.py test/test_train.py

A single run by hand

python rla_pinns/train.py \
  --equation=helmholtz --boundary_condition=room_modes \
  --wavenumber=12.0 --dim_Omega=3 \
  --N_Omega=3000 --N_dOmega=500 \
  --model=mlp-tanh-64-64-48-48 --num_steps=200 \
  --optimizer=RNGD --RNGD_approximation=exact --RNGD_damping=1e-8

RNGD_lr defaults to grid_line_search, so no learning rate is needed. Swap --optimizer=Adam --Adam_lr=1e-3 for the baseline. If l2_error is flat at ~1.0 from step 0, the target/solution pair is inconsistent — check the sign convention before blaming the optimizer.

Then run make lint. Docstring checks (darglint, pydocstyle) run in CI and are strict: every function needs a Google-style docstring with Args, Returns and Raises.

07

Running the sweeps

wandb sweeps, launched as SLURM job arrays. Two scripts and a folder of YAML.

Mechanics

Create rla_pinns/exp20_helmholtz3d/ with an __init__.py and copy rla_pinns/exp1_poisson5d/sweeps/ into it — that directory has the fullest set of configs (SGD, Adam, ENGD, HessianFree, ENGD_woodbury, SPRING, plus the nystrom, sap and pcg variants). Then: 

# 1. register each sweep with wandb and emit an sbatch script
python ../yaml_to_sh.py sweeps/ENGD_woodbury.yaml ENGD_woodbury --qos=m3 --array=50

# 2. submit
cd sweeps/ && sbatch ENGD_woodbury.sh

yaml_to_sh.py runs wandb sweep, scrapes the sweep ID out of its stderr, and writes sweeps/<same-name>.sh — an array job where each task runs wandb agent --count 1 <id>, i.e. one trial. --array=50 means 50 trials, capped at 17 concurrent. create_sweeps.sh and launch_sweeps.sh in each experiment folder are just comment-toggled lists of those two commands; edit them rather than typing by hand.

Two things will break on your cluster

The sbatch template is Vector-specific. create_sbatch_script in yaml_to_sh.py hard-codes --partition=rtx6000, a QUEUE_TO_TIME QOS map, and source ~/miniforge3/etc/profile.d/conda.sh. Edit that function for your scheduler — or skip SLURM entirely and run wandb agent --count 1 <id> in a loop.

Keep wandb pinned at 0.16.3. yaml_to_sh.py finds the sweep ID by string-matching "wandb: Run sweep agent with: wandb agent " in stderr. Newer wandb changed that message and the script fails with an unpacking error. If you upgrade, grab the ID by hand and paste it into the sbatch script.

What to edit in each YAML

Set entity and project to your own wandb account, then the problem block: equation: helmholtz, boundary_condition: room_modes, wavenumber, dim_Omega: 3, N_Omega, N_dOmega, model, num_seconds. Leave program: ../../train.py and the metric block alone.

Optimizer naming

The paper's three headline methods are all the same class, RNGD, separated by flags — this trips everyone up:

Paper nameFlagsSwept
ENGD (Woodbury)--optimizer=RNGD --RNGD_approximation=exact, momentum 0RNGD_damping
SPRINGsame, plus --RNGD_momentum > 0RNGD_damping, RNGD_momentum
ENGD / SPRING (Nyström)--RNGD_approximation=nystrom --RNGD_rank_val=Rsame + rank R
ENGD (dense baseline)--optimizer=ENGDdamping, ema_factor, initialize_to_identity
Adam / SGD--optimizer=Adam / SGDlr (and momentum)
Hessian-free--optimizer=HessianFreedamping, cg_max_iter

rank_val must be 0 for exact and > 0 for the randomized variants — an assert enforces it. RNGD_norm_constraint only has an effect when RNGD_lr is a float; with the default grid line search it is inert.

Damping is the knob that matters

Learning rate is handled by a grid line search and is never swept. Damping is, and its useful range is problem-dependent: the paper used 1e-15 … 1e-5 for 5-D Poisson but 1e-7 … 1e-3 for 4-D heat. Do not inherit either. Run one short pilot (num_seconds: 600, --array=20) with a wide 1e-12 … 1e-2 log-uniform range, look at where the good runs cluster, then narrow and run the real sweep.

Budget

num_seconds is per-trial wall clock (the paper used 3000–7000 s). At 50 trials and 17 concurrent, one optimizer's sweep is roughly 3–6 hours on 17 GPUs. For a feasibility test, run three sweeps first — Adam (the baseline anyone will compare against), ENGD_woodbury, and SPRING. Add the Nyström variants only if you push N_Omega + N_dOmega into the thousands, since that is the regime where the randomized approximations pay off.

08

Plots and results

Copy rla_pinns/exp16_heat4d_smallbatch/plot.py into your experiment folder. Set entity, project, equation, architecture and dim_Omega at the top, then run it once with print_sweeps = True to print the sweep IDs and their names. Fill those into the sweep_ids dict and run again.

It pulls the best run per sweep from the wandb API, caches it under best_runs/, and emits a 2×2 figure — loss and L2 error, against both step count and wall-clock time. That last axis is the point of the paper: per-step the second-order methods should win comfortably; per-second is where the Woodbury identity earns its keep. Use --local_files to re-plot without hitting the API.

09

Gotchas

  • Keep --dtype=float64. It is the default and the Gramian solves need it. On consumer GPUs float64 is heavily throttled; the sweep timings assume RTX 6000 / A100-class hardware. Dropping to float32 means re-tuning damping upward.
  • No complex-valued support. The network has one real output everywhere (set_up_layers, the residuals, the Gramian machinery). Impedance or radiating boundary conditions would need a two-output network and edits throughout — out of scope for a feasibility test.
  • Unparsed flags are fatal. check_all_args_parsed() raises on any leftover argument, so a typo in a sweep YAML kills every trial immediately rather than being ignored.
  • Batch size drives cost quadratically. Exact Woodbury is O(N²P) in N = N_Omega + N_dOmega. That is exactly the tradeoff against dense ENGD's O(P³), so pick N deliberately rather than copying it from an existing YAML.
  • Checkpoints rename RNGD. With --save_checkpoints, files are labelled ENGDw when momentum is 0 and SPRING otherwise — do not expect "RNGD" in the filenames.
  • Environment. make conda-env && conda activate rla_pinns, or pip install -e ".[lint,test]". Dependencies are pinned deliberately (torch 2.2.0, wandb 0.16.3); do not upgrade during the test.
